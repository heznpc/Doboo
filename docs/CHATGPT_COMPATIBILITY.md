# ChatGPT dots·Mini·Pets 호환성

아래는 현재 소스와 OpenAI 공식 문서를 대조한 기술 검토입니다. 실제 연동·업로드·watchOS 실행 호환성은 미검증입니다.

## 판단

Doboo의 캐릭터 외형을 ChatGPT Pets용 이미지로 옮기거나, 사용자가 제공한 Pet 스프라이트를 Doboo에서 재생하는 것은 별도 변환기와 렌더러를 만들면 가능합니다. 현재 앱에 바로 호환되는 구현은 없습니다. dots 에이전트나 Mini UI 자체를 watchOS 앱 안에 넣는 공식 임베딩 SDK/API는 확인한 공개 문서에서 찾지 못했습니다.

| 대상 | 현재 호환 여부 | 가능한 범위 |
| --- | --- | --- |
| ChatGPT Pets 이미지 | 직접 호환되지 않음 | 명시적으로 제공된 커스텀 스프라이트의 프레임 재생, 또는 Doboo 포즈를 규격 이미지로 내보내기 |
| ChatGPT Pet의 작업 상태 | 연결 없음 | 별도 작업 이벤트와 상태 매핑 필요. 이미지 파일만으로 채팅·작업 상태가 전달되지는 않음 |
| Mini | 이식할 캐릭터 없음 | ChatGPT 데스크톱의 간소화된 채팅 컨트롤이며 Doboo용 임베딩 계약은 확인되지 않음 |
| dots | 직접 호출·임베딩 경로 미확인 | Doboo에 서버 기능이 생길 경우 MCP 플러그인으로 도구를 제공하는 간접 연동 검토 가능 |

## Mini와 Pets의 차이

공식 문서에서 **Mini는 펫 없이 채팅 컨트롤을 표시하는 선택 항목**입니다. Pets는 작업 진행을 보여주는 애니메이션 외형이며, 펫을 바꿔도 ChatGPT의 작업 수행 방식은 바뀌지 않습니다. 데스크톱 오버레이는 macOS·Windows 기능입니다. 웹에서는 지원되는 Work 대화 안에 나타나며 데스크톱 오버레이와 같은 기능을 제공하지 않습니다. [OpenAI 공식 Pets 문서](https://learn.chatgpt.com/docs/pets)

따라서 “Mini/Pets를 Doboo에 넣기”는 외형 가져오기, ChatGPT 작업 표시, 채팅 기능 중 어느 범위를 구현하는지 나누어야 합니다. 외형을 가져와도 ChatGPT 세션·기억·작업 실행 기능이 함께 이동하지는 않습니다.

## 이미지 포맷과 버전 차이

공개 웹 문서는 커스텀 펫 업로드에 투명 PNG 또는 WebP, **1536 × 1872 픽셀**, 최대 **20 MiB**를 요구하며 업로드한 펫을 다운로드할 수 있다고 설명합니다. 데스크톱에서 만든 커스텀 펫은 로컬 저장되고 웹으로 자동 동기화되지 않습니다. [OpenAI 공식 Pets 문서](https://learn.chatgpt.com/docs/pets)

이와 별도로 `work-pets` 플러그인 **0.1.6**의 `references/sprite-sheet-contract.md`는 다음 형식을 기술합니다. 이는 해당 번들 문서에서 확인한 내용이며 모든 ChatGPT 클라이언트의 지원을 보장하는 공개 API 계약으로 간주하지 않습니다.

| 형식 | 이미지 크기 | 셀 크기·배치 | 필수 프레임 |
| --- | --- | --- | --- |
| v1 | 1536 × 1872 | 192 × 208, 8열 × 9행 | 57개 |
| v2 | 1536 × 2288 | 192 × 208, 8열 × 11행 | 73개 |

번들 문서의 공통 9행은 idle, running-right, running-left, waving, jumping, failed, waiting, running, review 순서이고 각 행의 프레임 수는 6·8·8·4·5·8·6·6·6입니다. `running`은 작업 처리 상태이며 좌우 달리기와 구분됩니다. v2에는 시선 방향 16개가 추가됩니다. 두 버전 모두 사용하지 않는 15개 셀은 투명해야 합니다.

공개 웹 문서와 번들 문서가 다른 크기를 제시하므로, 대상 클라이언트에서 v2 지원을 확인하기 전에는 “ChatGPT 전체 호환”을 표시할 수 없습니다. 입력 파일은 버전·크기·형식·프레임 수를 식별하고 알 수 없는 레이아웃을 거부해야 합니다.

## Doboo에 필요한 변경

현재 `DobooCharacterView`는 `SoftBlobShape`와 별도의 눈·입 도형으로 캐릭터를 그립니다. `SoftBlobShape`는 터치 좌표, 압박 강도, 호흡, 반동으로 곡선을 계속 바꿉니다. 스프라이트는 미리 그려진 프레임이므로 이 연속 변형과 동일한 동작을 담지 못합니다.

외형 호환을 구현한다면 기존 캐릭터 렌더러를 유지하면서 선택 가능한 스프라이트 렌더러를 추가하는 구성이 적합합니다. 다음 항목이 필요합니다.

1. 사용자가 제공한 이미지의 크기·형식·알파·셀 배치를 확인하고 필요한 프레임을 읽는 가져오기 경로.
2. 정해진 상태·프레임을 재생하는 렌더러와 Doboo 터치 동작의 매핑. 프레임 확대·이동만으로 현재의 국소 눌림이 보존된다고 간주하지 않기.
3. 화면 비활성화, 동작 줄이기, 디코딩 메모리와 프레임 캐시를 고려한 재생 정책. watchOS 기기에서의 성능은 별도 확인 필요.
4. Doboo를 ChatGPT로 내보낼 경우 각 Pet 상태에 해당하는 포즈 이미지와 규격 시트 생성. 현재의 calm·squint·surprised 표정만으로 전체 상태가 충족되지는 않음.

첫 구현 범위는 **사용자가 제공한 커스텀 펫의 외형 교환**으로 제한하는 것이 적합합니다. 기존 ChatGPT 계정의 펫 목록이나 내장 에셋을 자동으로 가져오는 연동으로 확대하지 않습니다.

## dots 연동의 경계

dots는 클라우드에서 작동하며, 연결한 컴퓨터와 사용자의 계정에서 활성화된 플러그인을 이용합니다. 컴퓨터 접근과 플러그인 권한은 별개이고, 로컬 컴퓨터 작업에는 온라인 상태와 실행 중인 ChatGPT 앱이 필요합니다. [OpenAI 공식 dots 연결 문서](https://learn.chatgpt.com/docs/dots/computers-and-apps)

문서상 확장 방향은 **dots가 Doboo의 도구를 이용하도록 제공하는 것**입니다. 이는 문서에 근거한 설계 가능성이며, 지금 Doboo에 지원되는 통합이 있다는 뜻은 아닙니다. 현재 저장소에는 서버, 계정 연결, 네트워크 API, MCP 도구가 없습니다. 원격 제어가 실제 제품 요구가 될 때 접근 가능한 서버, 사용자 인증·권한, watchOS로 상태를 전달하는 경로를 별도 설계해야 합니다.

ChatGPT용 MCP UI 역시 ChatGPT 내부 iframe에서 실행되는 웹 UI입니다. SwiftUI 화면을 그대로 가져오거나 ChatGPT의 dots·Mini UI를 Doboo에 내장하는 방식과는 다릅니다. [OpenAI 공식 MCP UI 문서](https://developers.openai.com/plugins/build/chatgpt-ui)

현재 촉감 캐릭터 제품 범위에는 원격 에이전트가 필요한 기능이 없으므로, 이 검토만으로 서버나 ChatGPT 인증을 추가할 근거는 없습니다. 호환성 구현 착수 시에는 대상 Pet 파일·클라이언트 버전 또는 구체적인 원격 동작을 먼저 확정해야 합니다.
